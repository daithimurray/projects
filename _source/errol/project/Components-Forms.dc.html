Button

Stable

Three variants, three sizes. Primary is Ink on light, Ochre on dark. One primary per view.

On Ink surfaces

Anatomy

  1. Container (height 40/48/56, radius 8)
  2. Label, Figtree 600, sentence case
  3. Optional leading icon, 20px, 8px gap
  4. Focus ring, 2px ink.500, offset 2

Usage

  • Primary: the one thing we want done (quote, call, book).
  • Secondary: alternatives beside a primary.
  • Ghost: low-emphasis inline actions, nav.
  • Label = verb + object, 1–3 words. Never “Submit”.
  • Full-width on mobile below 640px.

Accessibility

  • <button type>, or <a> when it navigates.
  • Min target 48×48 (Small gets 4px invisible padding).
  • Loading: aria-busy, keep label visible.
  • Disabled: aria-disabled stays focusable and explains why via tooltip.
  • Contrast: white on ink.800 13.5:1; ink on ochre.400 6.8:1.

Spec

<Button variant="primary" size="md"
  icon={<Phone/>} loading={false}>
  Get a quote
</Button>

--btn-h-md: 48px; --btn-px-md: 24px;
--btn-radius: var(--radius-2);
transition: background 150ms
  cubic-bezier(.2,0,0,1);

Icon button

Stable

Square button for a single, universally understood action: close, menu, next photo, favourite.

Anatomy

  1. Square container 40/48, radius 8 or 999
  2. Icon 16/20, centred
  3. Pressed state: ochre.50 fill, ochre.400 border

Usage

  • Only for icons users already know: ×, ☰, ‹ ›, ★.
  • Anything domain-specific (e.g. “eggshell”) gets a text button.
  • Round variant only over photos (gallery arrows).

Accessibility

  • aria-label required; tooltip on hover/focus shows the same text.
  • Toggles use aria-pressed, not colour alone (icon fills).
  • 48px target; 40px variant has 4px hit-slop.

Spec

<IconButton label="Close"
  variant="outline|ghost|solid"
  shape="square|round" size="md">
  <X/>
</IconButton>

Link

Stable

Inline text links are Ink 600 and underlined. Standalone links may drop the underline and add an arrow.

Read our guide to choosing a finish before you book, or see what’s included in every quote.

View all 42 projects Focused link Visited (ochre.800)
On dark: links go ochre.200, focus ring goes ochre.300.

Anatomy

  1. Text, inherits size
  2. Underline 1px, offset 3px (inline)
  3. Optional trailing arrow 16px (standalone)

Usage

  • Link text says where it goes; never “click here”.
  • Phone numbers and emails are always links (tel:, mailto:).
  • Standalone arrow links end sections, max one per card.

Accessibility

  • Inline links keep the underline; colour is not the only cue.
  • External links announce “opens in new tab” via visually hidden text.
  • Ink 600 on white 8.1:1; ochre.200 on ink.800 9.6:1.

Spec

a { color: var(--color-link);
  text-underline-offset: 3px; }
a:hover { color: var(--color-link-hover);
  text-decoration-thickness: 2px; }
a:focus-visible { outline: 2px solid
  var(--color-focus); outline-offset: 3px; }

Text input

Stable

48px tall, 16px text so iOS doesn’t zoom. Label always above; never placeholder-as-label.

Anatomy

  1. Label, 14px/500, 8px above
  2. Field 48px, radius 4, 1px plaster.300
  3. Optional prefix / leading icon
  4. Help or error text, 14px, 8px below

Usage

  • Placeholder shows format only (“BA1 2AB”), never instructions.
  • Validate on blur, re-validate on input once errored.
  • Use the right inputmode: tel, email, numeric.
  • Autocomplete attributes on every contact field.

Accessibility

  • Explicit <label for>; help via aria-describedby.
  • Error: aria-invalid + text + icon, not just red.
  • Border 3:1 against white (plaster.300 is 2.4:1 — so we add a 2px focus ring and rely on label; document this).
  • 16px text prevents mobile zoom.

Spec

<TextField label="Eircode"
  placeholder="W23 F2P4" inputMode="text"
  autoComplete="postal-code"
  error="Enter a full Eircode"
  prefix="€" leadingIcon={<Search/>}/>

height 48 · padding 0 16 · radius 4
border 1px plaster.300 → focus 2px ink.500
error 2px error.500 · disabled bg plaster.100

Textarea

Stable

For “tell us about the job”. Grows with content up to 12 lines, then scrolls.

Anatomy

  1. Label
  2. Field, min 120px, padding 12/16
  3. Help left, counter right

Usage

  • One per form. Mark optional in help text, not the label.
  • Counter appears at 80% of limit.
  • Vertical resize only.

Accessibility

  • Counter is aria-live="polite", announced at 90% and limit.
  • Same label / describedby rules as Text input.

Spec

<TextArea label="Tell us about the job"
  maxLength={600} autoGrow maxRows={12}
  help="Optional. Photos help more."/>

Anatomy

  1. Trigger, same box as input
  2. Chevron 20px, plaster.600
  3. Menu: radius 8, shadow md, 6px inset

Checkbox

Stable

Pick any: rooms to paint, extras to include, consent.

Anatomy

  1. Box 20px, radius 4, 2px plaster.500 border
  2. Checked: ink.800 fill, 3px white check
  3. Indeterminate: 10×2.5 dash
  4. Label 16px, 12px gap; optional description 14px

Usage

  • Groups of 2–8. More than 8: split into sections.
  • Card variant for priced extras.
  • Never pre-check consent or marketing.

Accessibility

  • Native <input type="checkbox"> visually hidden, custom box via :checked + span.
  • Whole label row is the 48px target.
  • Group in <fieldset> with <legend>.
  • Border plaster.500 on white 4.4:1 — passes 3:1 for UI.

Spec

<Checkbox label="Ceilings" checked
  description="…" variant="plain|card"
  indeterminate={false}/>

Radio

Stable

Pick one: finish, timing, how you’d like us to reply.

Anatomy

  1. Circle 20px, 2px plaster.500
  2. Selected: 6px ink.800 ring (8px white dot)
  3. Card variant: 2px ink.800 border + ink.50 fill when selected

Usage

  • 2–5 mutually exclusive options; 6+ becomes a Select.
  • Default to the most common choice when safe; otherwise none.
  • Card variant when each option needs a second line.

Accessibility

  • Native radios in a <fieldset>; arrow keys move selection.
  • Legend is the visible question.
  • Card selection uses border + fill + dot: three cues.

Spec

<RadioGroup legend="Finish" name="finish"
  variant="plain|card" options={[…]}/>

Switch

Stable

Instant on/off with immediate effect: “Include VAT”, “Show before photos”. Not for form submission.

Anatomy

  1. Track 44×24, radius 999
  2. Thumb 20px, 2px inset, shadow sm
  3. On: ink.800 track + check in thumb

Usage

  • Effect is immediate; if it needs “Save”, use a Checkbox.
  • Label states the on-condition. Never “Enable / Disable”.

Accessibility

  • role="switch" + aria-checked; Space toggles.
  • Check icon in thumb so state isn’t colour-only.
  • Off-track plaster.400 on white 2.7:1 — acceptable as a component boundary, thumb shadow adds edge.

Spec

<Switch label="Prices inc. VAT"
  checked onChange={…}/>
thumb transition: left 150ms ease-out

Form field & layout

Stable

The wrapper that gives every control its label, help, error, and spacing. Forms are single-column; pairs only for tightly related fields.

How should we reply?
Usually replied to within one working day.

Anatomy

  1. Label row (label left, “Optional” right)
  2. Control
  3. Help / error / success text
  4. 24px between fields, 16px within a pair

Usage

  • Mark optional, not required. Most fields are required.
  • Max form width 560px; one column.
  • Submit button left-aligned with a reassurance line beside it.
  • Errors summary at top on submit, linking to each field.

Accessibility

  • Error summary gets focus and role="alert".
  • Help text linked with aria-describedby, error appended to it.
  • Autocomplete on all identity fields (WCAG 1.3.5).

Spec

<Field label="Phone" optional
  help="We’ll only call if…"
  error={errors.phone}>
  <TextInput inputMode="tel"/>
</Field>
form gap 24 · pair gap 16 · max-w 560

Anatomy

  1. Drop zone: 2px dashed plaster.300, radius 8
  2. Icon 28, instruction, constraints line
  3. File row: 48px thumb, name, status, remove
  4. Progress bar 4px ink.800

Usage

  • On mobile the zone becomes a 48px button “Add photos” opening camera or library (accept="image/*").

Quantity stepper

Stable

Counting rooms, doors, windows. Small ranges (0–20) where tapping beats typing.

Anatomy

  1. − button 48px
  2. Numeric input 56px, centred, 600
  3. + button 48px

Usage

  • Ranges ≤ 20. Beyond that use a Text input.
  • Typing is always allowed; clamp on blur.

Accessibility

  • Buttons labelled “Fewer / More bedrooms”.
  • Input role="spinbutton" semantics come free from type="number"; we use text + inputmode to avoid scroll-wheel changes and announce via aria-live.

Spec

<Stepper label="Bedrooms" min={0}
  max={20} value={3}/>

Segmented control

Stable

2–4 short, exclusive options that change a view: Interior / Exterior, Before / After, Home / Commercial.

Anatomy

  1. Track: plaster.100, radius 8, 4px inset
  2. Segment 40px, radius 6, 20px sides
  3. Selected: white + shadow sm (ochre.400 on dark)

Usage

  • Labels ≤ 12 characters; equal widths on mobile.
  • Changes the view instantly; not a form input (use Radio).
  • Not for navigation between pages (use Tabs).

Accessibility

  • role="radiogroup" with role="radio" children; arrows move, one tab stop.
  • Selected differs by weight + fill + shadow, not colour alone.
  • Selection thumb animates 150ms; disabled under reduced motion.

Spec

<Segmented options={["Interior",
  "Exterior","Commercial"]} value={…}
  tone="light|dark" fullWidth/>
